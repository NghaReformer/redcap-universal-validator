REDCap's number validation takes one minimum and one maximum, and only warns. A lab value has two kinds of limit: the range most patients fall in, and the range outside which the number is almost certainly a typing or unit error. @UVRANGE checks both when the field is left and again when the form is saved. Outside the soft range the value is unusual and the save asks first; outside the hard range it is implausible and the save is held.

Syntax

JSON form only. At least one of soft and hard.

@UVRANGE={"soft":[12,17.5],"hard":[3,25],"unit":"g/dL"}

@UVRANGE={"soft":[null,140],"softBlock":"off","hard":[40,250],"hardBlock":"confirm","unit":"mmHg"}

@UVRANGE={"soft":[12,15.5],"hard":[3,25],"unit":"g/dL","when":"[sex]='2'"}
@UVRANGE={"soft":[13.5,17.5],"hard":[3,25],"unit":"g/dL","when":"[sex]='1'"}
KeyMeaning
soft[low, high], both ends included. Outside it the value is unusual. null leaves an end open
hard[low, high], both ends included. Outside it the value is implausible. The soft limits must lie inside the hard ones
softBlockconfirm (default): the save asks first; off: the note only
hardBlockhard (default): the save is held; confirm: the save asks first
unitA short label shown in the note, such as g/dL (up to 20 characters)
message, when, caseSensitive As for the other tags

Limits and values are compared as exact decimals, so 17.50 equals 17.5. A limit is kept exactly as written, quoted or not, so 0.12345678901234567890 keeps all twenty digits. blockSave is refused: use softBlock and hardBlock.

Field types

Text fields with integer or number validation (any number of decimals, comma decimals included) or with no validation, calc fields and sliders. On a comma-decimal field 17,5 reads as 17.5 and the note writes the limits with a comma. A Text field without validation accepts anything, so a value that is not a number is reported as implausible.

What is checked, and when

  • A blank field checks nothing. Pair the field with @UVREQUIRED when it must be filled.
  • The note appears when the field is left, not while a number is being typed. Clicking Save checks the value as it is, left or not.
  • A value inside the soft range shows no note. The tag only speaks about numbers that need a second look.
  • A calc field is noted but never holds the save, since nobody typed it. A read-only field is the same.
  • Different limits per group: one tag per group, each with its own when. When no when is true the field is not checked; add one tag without when to cover everyone else. A selector on another form is read when the page opens, so that check is advisory and never blocks.
  • With event and instance references turned on in the project settings, when may read another event or instance, such as [baseline_arm_1][sex]. Such a rule never blocks on the page; the audit and the scan check it. The references key is refused.
  • The exponent form REDCap's number validation accepts is a number: 1.5E1 is 15. Thousands separators (1,200) and a unit typed into the box are not numbers.
  • A field marked with one of the project's missing data codes (UNK, -99) holds the code, not a number. It is treated as blank, on the page, in the audit and in the scan.

Growth references

With reference, the limits apply to the value's z-score for the child's sex and age, or length or height, computed the way WHO's own anthro software computes it.

@UVRANGE={"reference":"who-wfa","sex":"[sex]","male":"1","female":"2",
          "age":{"dob":"[dob]","at":"[visit_date]"},"soft":[-2,2],"hard":[-5,5]}

@UVRANGE={"reference":"who-wfh","sex":"[sex]","male":"1","female":"2",
          "by":"[height_cm]","soft":[-3,3],"hard":[-5,5]}
KeyMeaning
referenceThe reference: who-wfa, who-lhfa, who-bfa, who-hcfa, who-acfa, who-ssfa, who-tsfa, who-wfl, who-wfh (WHO 2006, birth to 5 years) or who2007-wfa, who2007-hfa, who2007-bfa (WHO 2007, 5 to 19 years)
sex, male, femaleThe field holding the sex, and the codes it stores for male and for female
age{"dob":"[dob]","at":"[visit_date]"}, {"days":"[age_days]"} or {"months":"[age_months]"}
byFor weight-for-length or weight-for-height: the field holding the length or height in cm
soft, hardz-score limits, from -20 to 20
  • A value that is not a number, or a measurement of 0 or below, is implausible whatever the inputs say.
  • A blank input, a sex code that is neither male nor female, and an age or length outside the reference check nothing. On a data entry form a grey note says why.
  • Inputs on another form, or in another event, are read when the page opens and the rule's note does not block there. A survey, and a user without rights to that form, are not sent their values: the page checks only that the value is a number above 0, and holds the save when it is not; the z-score is checked when the record is saved.
  • WHO's 0.7 cm correction for a length measured standing, or a height measured lying, is not applied: pick who-wfl (lying) or who-wfh (standing). For a child with oedema, skip weight rules with when.
  • The WHO tables ship with the module under WHO's GPL-3 licence. A REDCap administrator can add other references (CDC 2000, a national one) in a folder named in the module's system settings.

Audit

The post-save audit logs a value outside either range as type: range with reason soft-low, soft-high, hard-low, hard-high, not-a-number or, for a growth reference, not-positive, whatever softBlock says, and the Validation scan counts it. The scan's report, when it returns, labels each one an unusual value, an implausible value, not a number or (for a growth reference) not a positive measurement, with the expected or allowed range.
